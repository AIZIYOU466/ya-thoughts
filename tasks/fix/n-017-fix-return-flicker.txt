问题 1：从编辑页返回列表页时，先看到纯蓝背景，再看到内容（闪一下）
═══════════════════════════════════════

用户现象：
- 点编辑页左上角小箭头返回 → 第一眼看到的是纯蓝的背景（body 渐变），
- 然后列表内容才"跳"出来。
- 观感像页面重加载，不流畅。

排查方向：
1. 找到 hideEditorWithTransition() 函数。
2. 检查执行顺序：
   a. 什么时候移除 #editor-view 的 .active？
   b. 什么时候显示 #list-view？
   c. 这两步之间是否有时间差（哪怕 1 帧）？
3. 检查 #list-view 的 visibility 状态：
   a. 编辑页打开期间，#list-view 是 visibility: hidden 吗？
   b. 返回时，什么时候把 visibility 改成 visible？
   c. 如果 visibility 改 visible 和 .active 移除不同步，会出现"看到背景"的瞬间。
4. 检查 .no-blur 的移除时机：
   a. .no-blur 是在动画结束还是动画开始移除？
   b. 如果 .no-blur 移除时列表页还在重建，会闪一下没模糊的状态。
5. 检查是否有其他元素在返回时被切换（比如 #list-header、#new-bar 的可见性）。

预期根因（供参考）：
- #list-view 在编辑页打开时是 visibility: hidden，返回时先把它设为 visible，
  再移除编辑页的 .active，中间有一帧是"列表页还没渲染完但已经 visible"。
- 或者 .no-blur 移除太早，列表页的 backdrop-filter 还没生效就露出背景。

═══════════════════════════════════════
问题 2：底部胶囊（笔记/待办）的文字被压成两行
═══════════════════════════════════════

用户截图：
- 左胶囊："笔"和"记"分两行
- 右胶囊："待"和"办"分两行

排查：
1. 找到 .new-cap 的 CSS 规则。
2. 检查是否有：
   a. white-space: nowrap？
   b. 固定的 min-width 或 width？
   c. flex-wrap 相关的规则？
3. 检查父容器 #new-bar 的宽度和 gap：
   a. #new-bar 是否设置了固定宽度？
   b. gap 是否太大，把子胶囊挤窄？
4. 检查胶囊内部的布局：
   a. 是 flex 布局吗？
   b. 图标和文字的间距是否合理？
   c. 是否有 max-width 限制？

预期修复：
- 给 .new-cap 加 white-space: nowrap。
- 给 .new-cap 加 flex-shrink: 0。
- 给 #new-bar 加 width: auto（不要固定宽度）。

═══════════════════════════════════════
问题 3：底部胶囊有边框闪烁
═══════════════════════════════════════

用户现象：
- 进入列表页时，笔记/待办按钮出现一个边框，一闪。
- 两个按钮本身没闪，只是边框闪。

排查：
1. 检查 .new-cap 的 border 定义：
   a. border 是固定值还是随状态变化？
   b. 有没有 transition 涉及 border？
2. 检查 .no-blur 给 .new-cap 加的 background-color: var(--glass-bg-strong) !important：
   a. 移除 .no-blur 时，背景色突然变化，边框跟着重绘，可能闪一下。
   b. 这个 background-color 是否必要？能不能只移除 backdrop-filter 而不改背景？
3. 检查 border-color 是否依赖 CSS 变量：
   a. 如果 --glass-border 在切换瞬间被重算，边框会闪。
   b. 改成固定色值试试。

预期修复：
- 移除 .no-blur 里给 .new-cap 的 background-color 覆盖，只保留 backdrop-filter: none。
- 或者给 .new-cap 加 border 的 transition: none。
- 让 .new-cap 在切换期间不重绘。
