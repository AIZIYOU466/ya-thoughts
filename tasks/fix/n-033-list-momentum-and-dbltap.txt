问题 1：vAnimating 卡死（严重）
═══════════════════════
用户报告：点击图片打开查看器，双击后整个页面卡死，什么也动不了，只能清后台。

已知线索：
- L5129: if (vAnimating) return; // 双击动画进行中：忽略新手势
- grep 全文只在 L5129 看到 vAnimating 的读取，没看到哪里写入 true/false

请排查：
1. 搜索 vAnimating 的所有出现位置（读和写），列出每一处的行号。
2. 如果只有读取没有写入，说明这个变量从没被设为 true——那 L5129 不是卡死原因，需要找别的原因。
3. 如果只在某个地方设为 true 但没有地方设回 false → 这就是卡死的根因。
4. 检查 applyDoubleTapZoom 函数（L5215-5234 附近）的完整实现：
   a. 是否在动画开始前设 vAnimating = true？
   b. 动画结束后（transitionend 或 setTimeout）是否设回 false？
   c. 如果依赖 transitionend，是否有 fallback 定时器？（transitionend 在某些情况下不触发）
5. 检查 vGesture 状态机是否有遗漏的分支：
   a. 是否有路径把 vGesture 设成某个值但永远不重置？
   b. touchend 在双指变单指、单指抬起等场景下是否正确重置为 idle？

必须明确输出：
- vAnimating 的完整生命周期（哪里设 true、哪里设 false、如果没有 false 就是 bug）

- 卡死的精确原因（哪一行代码、什么条件下）

修复方向：
- 给 vAnimating 加一个保底定时器：设 true 后 400ms 强制设回 false，无论 transitionend 是否触发。
- 或者用 vAnimating + vAnimatingTimer 双保险。
- 检查所有手势路径，确保 vGesture 最终能回到 idle。

问题 2：列表惯性滚动不够丝滑
═══════════════════════
用户报告：列表上下滑动生硬，没有惯性和弹性。

已知线索：
- 惯性滚动已实现（L2845-2889 momentumStep 等）
- 但用户觉得不丝滑

请排查 momentumStep 的完整实现，输出：
1. 减速度系数是多少（每帧速度乘多少）？
2. 最小停止阈值是多少（速度小于多少就停）？
3. 边界回弹（滚到顶部/底部时的弹性）是否实现？怎么实现的？
4. 采样函数 sampleVelocity 怎么计算初始速度？
5. 每帧的时间步长怎么处理（是否用了 dt 归一化）？

对比 iOS 原生滚动的参数：
- iOS 减速度约 0.998/ms（每毫秒速度乘 0.998）
- 停止阈值约 0.05 px/ms
- 边界回弹用 spring 或指数衰减

修复方向：
- 如果减速度太快（比如每帧乘 0.9），改成 0.995/ms（更接近原生）。
- 如果停止阈值太高（比如 0.5 px/ms），改小到 0.05。
- 如果边界回弹没做或做得硬，改用指数衰减：位移 = 初始位移 * e^(-t/τ)，τ 约 300ms。
- 如果 sampleVelocity 只采样最近一次移动，改成滑动窗口（最近 100ms 内的平均值）。
