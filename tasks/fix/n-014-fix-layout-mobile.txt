排查方向（在手机视口下重新分析）
═══════════════════════════════════════

关键约束：
- 手机 viewport 是 360-430px。
- 任何 max-width: 640px 之类的大值，在手机上都不会生效（因为屏幕本来就窄）。
- 所以"右侧 40% 空白"不是 max-width 引起的，而是别的原因。

按以下顺序排查：

1. **检查 body / html 的实际宽度**
   - 在浏览器里用 devtools 或者 jsdom 模拟 390px 宽度，看 document.body.offsetWidth 是多少。
   - 是否 = 390？还是被某处约束成 234（60%）？

2. **检查 #list-view 的实际宽度**
   - 在 390px 视口下，它的 offsetWidth 是多少？
   - 如果 < 390，找出哪个属性在限制它。

3. **检查是否有容器用了固定百分比宽度**
   - 搜索 width: 50%、width: 60%、width: 33%、width: calc(...) 的用法。
   - 特别注意液态玻璃重做时新加的 .editor-panel、#new-bar 等容器。

4. **检查是否有 transform: scale 或 translate 影响视觉宽度**
   - 搜索 transform: scale、transform: translateX 的用法。
   - 液态玻璃重做时可能引入了缩放或位移。

5. **检查是否有 position: absolute / fixed 的元素宽度算错**
   - 编辑页的顶栏按钮为什么挤在左侧一小块？它们应该是 flex 分布在全宽。
   - 检查 #editor-view 内部的 header 容器。

6. **检查 .editor-panel 的宽度规则**
   - 它现在是 width: 100% 还是 calc(100% - 24px) 还是别的？
   - 它内部有没有 margin-left / margin-right 过大？

7. **检查是否有横向滚动**
   - 页面能否横向滚动？如果能，说明有元素超出视口宽度，把其他内容"挤"到了左侧。
   - 加临时测试：在浏览器 console 里跑 document.documentElement.scrollWidth，看是否 > 视口宽度。

8. **检查 CSS 里是否有写错的单位**
   - 比如 width: 100vw 但计算时被 margin 撑爆。
   - 或者 width: 100% 但父容器宽度是 0。

9. **检查最近一次 git diff**
   - git diff HEAD~1 -- index.html 看看 v1.4.3 → v1.5.0 具体改了哪些 CSS 规则。
   - 特别关注：新增的容器、修改的宽度/定位规则。
