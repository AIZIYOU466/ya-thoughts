## 模块 1：引导弹窗加"去设置"按钮（跳系统应用详情页）

现状：引导弹窗（showNotifyGuide 函数）只有"稍后再看"和"我已设置好"两个按钮。

用户需求：能真正跳到系统的"应用详情页"或"应用设置页"，让用户在那里开自启动/电池白名单。

技术限制：Capacitor 官方 App 插件没有"打开系统设置" API。需要写原生代码。

实现方案（推荐：写 Java 自定义方法）：
1. 修改 android/app/src/main/java/com/yathoughts/app/MainActivity.java
2. 通过 Capacitor 的 Bridge 暴露一个 JS 可调用的方法 openAppSettings
3. 内部用：
   Intent intent = new Intent(Settings.ACTION_APPLICATION_DETAILS_SETTINGS);
   intent.setData(Uri.parse("package:" + getPackageName()));
   startActivity(intent);
4. JS 侧调用方式：在 AI 报告里说明清楚（Capacitor 8 支持的暴露方式）

如果 Java 方案不可行（比如 Capacitor 8 的 Bridge API 限制），备选：
- 装 npm 插件（如 capacitor-plugin-app-settings）——但要确认支持 Capacitor 8
- 或者退回"复制包名"按钮，让用户自己去找

弹窗改动：加一个按钮"去设置"，点了调上述方法。

## 模块 2：编辑页两个时间字段一起显示

现状交互（用户原话）：
1. 点"设置提醒" → 底部弹卡片 → 只有"提醒时间"字段
2. 设置完成后关闭
3. 再次点"设置提醒" → 卡片里同时有"提醒时间"和"截止时间"
4. 点截止时间设置并关闭 → 只显示提醒时间的小胶囊，截止时间小胶囊没出现

目标：
- 点一次"设置提醒"就同时显示两个字段（提醒时间 + 截止时间）
- 设完截止时间后，卡片上两个小胶囊都显示

诊断方向：
- 看 due-pop 面板里 end-row 的显隐逻辑（可能在 syncEditorTodoUI 或类似函数里）
- 看小胶囊（due-badge）的渲染逻辑是否漏了 endAt

## 模块 3：回收箱手势返回

现状：打开回收箱 → 侧滑返回 → 无反应（不关箱、不退 App）

重要线索：编辑页的手势返回曾经有同样问题，但已修好。用户希望回收箱套用同样的逻辑。

诊断方向：
1. 先看编辑页手势返回是怎么修的——在 backButton 监听器（约 6520~6600）里
2. 对比回收箱的处理
3. 找出为什么编辑页好了而回收箱没好

当前两处代码看起来一样：
- 编辑页：if (editor-view.classList.contains('active')) { back-btn.click(); return; }
- 回收箱：if (binMaskEl.classList.contains('open')) { bin-back.click(); return; }

可能差异：
- binMaskEl 引用在监听器注册时是 undefined
- 回收箱打开时的 class 不是 'open'（比如是别的）
- 或者回收箱在某个 DOM 里，被其他层拦截

要求 AI：先诊断，贴出实际代码对比，找出差异再改。

## 模块 4：列表 4 张卡也能滑

现状：4 张卡片时上下完全滑不了，5 张可以轻微滑动。

目标：任何数量（包括 1 张）都能上下滚动。

诊断方向：
- 看列表容器 CSS（height/overflow/flex）
- 可能是 min-height 或容器高度被内容撑开

修改方向：
- 确保容器高度固定/视口限制
- overflow-y: auto 或 scroll
- 可能需要给容器设置 height: 100% 之类

## 模块 5：列表惯性 + 卡片左右滑惯性

用户需求：
- A. 列表上下滚动的惯性（iOS 那种滑一下继续滚）
- B. 卡片左右滑的惯性

实现方向：
- 列表惯性：CSS 加 -webkit-overflow-scrolling: touch;
- 卡片左右滑：如果是自定义触摸事件，需要自己算速度衰减

诊断方向：
- 看列表滚动是原生 overflow 还是 JS 控制
- 看卡片左右滑是谁实现的（哪段代码）
