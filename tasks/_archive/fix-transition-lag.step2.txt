═══════════════════════════════════════
第 2 步：优化切换流畅度
═══════════════════════════════════════

现状：动画已经出来了，但不够丝滑，且概率性卡顿。
根因：backdrop-filter 在切换期间的重绘开销 + 动画曲线不够柔和。

═══════════════════════════════════════
修复 1：切换期间冻结 backdrop-filter
═══════════════════════════════════════

新增 CSS（精准写法，不要用 .no-blur *）：

.no-blur,
.no-blur #list-header,
.no-blur #search-wrap,
.no-blur #seg-bar,
.no-blur .new-cap,
.no-blur .editor-panel,
.no-blur .editor-bar,
.no-blur .editor-toolbar,
.no-blur #new-bar {
  -webkit-backdrop-filter: none !important;
  backdrop-filter: none !important;
  background-color: var(--glass-bg-strong) !important;
}

说明：去掉 backdrop-filter 后，把背景色加深一点（用 --glass-bg-strong
或直接给一个不透明色），避免元素变透明后看不见。

JS 改动：
- 页面切换开始前（show('editor') 或 hideEditorWithTransition 开头）：
  document.body.classList.add('no-blur');
- 切换结束后（transitionend 或超时兜底 340ms）：
  document.body.classList.remove('no-blur');
- 关键：移除 .no-blur 要延迟到切换完全结束后，不要在动画中途移除。

═══════════════════════════════════════
修复 2：will-change 只在切换期间挂
═══════════════════════════════════════

- 切换前：给 #list-view 和 #editor-view 加 style.willChange = 'transform, opacity'
- 切换后 300ms：清除 style.willChange = ''
- 不要常驻 will-change（会占用 GPU 内存）

═══════════════════════════════════════
修复 3：优化动画曲线，让它更柔和
═══════════════════════════════════════

当前 260ms cubic-bezier(0.32, 0.72, 0, 1)。
这个曲线"前段快后段慢"，如果时长太短会显得急。

调整：
- 时长从 260ms 延长到 320ms（更从容）
- 曲线改为 cubic-bezier(0.22, 1, 0.36, 1)（更柔和的 out 曲线）
- opacity 和 transform 用同一曲线

═══════════════════════════════════════
修复 4：检查还有哪些重绘源
═══════════════════════════════════════

检查切换期间是否还有其他重绘开销：

a. 编辑页内的图片（<img>）：如果编辑页有图片，切换时图片解码也会占时间。
   建议：编辑页默认隐藏时，图片加 loading="lazy"。

b. 编辑页的 backdrop-filter 元素（.editor-panel、.editor-bar、.editor-toolbar）：
   切换时这些也要冻结（修复 1 已覆盖）。

c. box-shadow 或 filter：搜索切换动画期间是否触发了 box-shadow 变化，如果有，改成固定值。

d. 文本渲染：编辑页的 contenteditable 在切换时如果重新计算文本布局，也会占时间。
   建议：切换前给编辑器加 content-visibility: hidden，切换后移除。
   但这个改动有风险，先不做，观察效果。

═══════════════════════════════════════
执行方式
═══════════════════════════════════════

先做修复 1、2、3。
修复 4 只是检查，如果发现明显问题再处理。

做完让用户测试：
1. 进入编辑页、返回列表页的流畅度
2. 还有没有概率性卡顿

═══════════════════════════════════════
严格约束
═══════════════════════════════════════

- 不改布局宽度。
- 不改功能逻辑。
- 保留液态玻璃视觉效果（切换稳定后仍有模糊）。
- 切换动画用 transform + opacity。
- 分步执行：先做修复 1（no-blur），测试；如果还卡再加修复 2、3。
  但为了减少往返，可以一次做完修复 1+2+3，如果效果不好再回滚。

输出要求
═══════════════════════════════════════

- 报告：修改的行号、新增的 CSS 规则、JS 中切换逻辑的改动位置
- 让用户测试后反馈：流畅度是否提升，还有没有概率性卡顿
