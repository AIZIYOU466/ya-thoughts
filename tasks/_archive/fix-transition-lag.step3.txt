第 3 步：诊断三个问题
═══════════════════════════════════════

用户实测反馈（v1.5.x，第 2 步改动后）：

1. 列表页 → 编辑页：有滑入动画，但不够丝滑。
2. 编辑页 → 列表页：看不到动画，或者动画过渡不明显。
3. 多次重复"进编辑页 → 返回"后，流畅度下降。

第 3 点是重点：**资源泄漏**。必须先诊断，不要直接改。

执行方式（systematic-debugging）
═══════════════════════════════════════

先输出三个问题的根因报告，等确认后再动手。

═══════════════════════════════════════
问题 1 诊断：列表→编辑页不够丝滑
═══════════════════════════════════════

排查：
1. 检查 .no-blur 是否在切换开始**之前**就添加了？
   如果添加顺序在 transition 触发之后，backdrop-filter 会在动画第一帧还在计算。
2. 检查 #list-view 和 #editor-view 是否都加了 will-change？
3. 检查是否有其他元素在切换期间重绘（搜索框、分段控件、卡片阴影）。
4. 检查动画曲线 cubic-bezier(0.22, 1, 0.36, 1) 是否符合预期。

═══════════════════════════════════════
问题 2 诊断：编辑→列表无动画（关键）
═══════════════════════════════════════

这是最需要搞清楚的问题。排查：

1. 找到 hideEditorWithTransition() 函数，逐行读它的逻辑。
2. 确认执行顺序：
   a. 添加 .leaving 类时，#editor-view 当前有 .active 吗？
   b. .leaving 的 transform: translateX(100%) 是否会被 transition 驱动？
   c. transitionend 事件是否立即触发（因为某些属性瞬间变化）？
3. 检查 CSS 里 .leaving 的规则是否被其他更高优先级的规则覆盖：
   - 比如 #editor-view.active 的 transform: translateX(0) 是否比 .leaving 优先级高？
   - 检查选择器权重：#editor-view.active (0,2,0) vs #editor-view.active.leaving (0,3,0)，.leaving 应该更高。
4. 检查 transitionend 的监听：
   a. 监听的属性是 transform 还是 opacity？
   b. 如果同时监听两个，是不是第一个触发（比如 opacity 先完成）就把动画结束了？
5. 检查 removeEventListener 是否在 transitionend 里调用，避免重复绑定。
6. 关键疑问：添加 .leaving 后，是否有立即的 requestAnimationFrame 或 setTimeout 把 .active 移除？
   如果立即移除，.active 和 .leaving 同时消失，transform 会瞬间回到基础态，看起来"没有动画"。

请明确回答：
- hideEditorWithTransition() 的完整执行流程
- .leaving 添加后，什么时候移除 .active？什么时候移除 .leaving？
- transitionend 监听在哪个元素上？监听哪些属性？

═══════════════════════════════════════
问题 3 诊断：多次操作后流畅度下降（重点）
═══════════════════════════════════════

这是资源泄漏信号。排查：

1. 事件监听器泄漏：
   a. 每次 show('editor') / hideEditorWithTransition() 时，是否绑定了新的 transitionend / setTimeout 监听？
   b. 这些监听有没有在正确时机移除？
   c. 如果每次切换都 addEventListener('transitionend', ...) 但没 removeEventListener，监听器会累积。

2. will-change 泄漏：
   a. 切换结束后，style.willChange = '' 是否真的执行了？
   b. 如果中途报错，will-change 会残留。

3. .no-blur 泄漏：
   a. 移除 document.body.classList.remove('no-blur') 的时机是否正确？
   b. 如果动画被中断（比如用户快速点击），.no-blur 会不会残留？

4. setTimeout 泄漏：
   a. 每次切换是否启动新的 setTimeout？
   b. 旧的 setTimeout 有没有清理？
   c. 快速重复操作时，多个 setTimeout 同时跑，每个都尝试移除 .no-blur / 清 will-change，可能互相干扰。

5. 内存占用：
   a. 检查是否有变量累积（比如数组、Map 每次切换都 push 但不清空）。
   b. 检查编辑页的 contenteditable 是否累积了历史记录（undo/redo 栈）。

请明确回答：
- 每次切换过程中，哪些监听器 / 定时器 / 类被添加，分别在什么时候移除？
- 快速重复切换时，是否存在多次添加但只移除一次的情况？
