现象（关键：只有"编辑过"才出现）
═══════════════════════════════════════

用户描述：
- 打开便签，**编辑内容**（改文本、加字等）。
- 点编辑页左上角返回箭头，回列表页。
- 返回期间：
  a. 编辑页的回退动画（滑出）会变卡。
  b. 列表页也会闪烁、变卡。

对比：
- **没编辑过**（只打开看看就返回）→ 返回动画流畅，不卡。
- **编辑过**（改了内容）→ 返回卡、闪烁。

关键线索：**编辑操作触发了某些副作用，这些副作用在返回时集中爆发。**

═══════════════════════════════════════
根因排查（systematic-debugging 流程）
═══════════════════════════════════════

按以下顺序排查，每个都要给出代码行号证据：

【排查 1：blur 事件触发 autosave】
1. 找到编辑器的 blur 事件处理（contenteditable 或输入框的 blur / focusout 监听）。
2. 检查：点击返回箭头时，编辑器失去焦点，blur 是否同步触发了 autosave？
3. autosave 里做了什么：
   a. 是否同步写 IndexedDB（dbPut）？
   b. 是否更新 note.updatedAt？
   c. 是否触发 renderList 或 DOM 更新？
4. 关键：如果 blur 在返回动画开始的同一帧执行同步 IndexedDB 写入，
   会阻塞主线程，导致动画首帧卡顿。

【排查 2：返回时的定向更新逻辑】
1. 找到 backToList() 函数。
2. 逐行读它对目标卡片的更新逻辑：
   a. 更新 .title / .summary / .time 时，是否每次都调用 textContent？
   b. 是否重新测量摘要（summaryOverflows）？
   c. 是否重新计算相对时间（relativeTime）？
   d. 是否有任何 getComputedStyle / offsetHeight / scrollHeight 等强制回流调用？
3. 关键：编辑后，摘要可能变长、时间戳更新、可能需要重新测量。
   如果这些同步操作在返回动画的首帧执行，会卡。

【排查 3：卡片排序和移动】
1. 如果排序是按"修改时间倒序"，编辑后 updatedAt 更新，卡片要移到列表顶部。
2. 检查：
   a. 返回时是否调用了排序逻辑？
   b. 是否用了 DOM insertBefore / appendChild 移动卡片？
   c. 移动时是否有 CSS transition 触发？
   d. 是否触发其他卡片的位移动画？
3. 关键：DOM 移动 + CSS transition + 其他卡片让位，
   如果在返回动画期间执行，双重动画叠加导致掉帧。

【排查 4：.no-blur 移除时机】
1. 找到 .no-blur 的挂载和移除逻辑。
2. 检查移除时机：
   a. 是在返回动画结束后移除，还是同时移除？
   b. 移除 .no-blur 时，所有玻璃元素（顶栏、搜索框、分段控件、
      底部胶囊、卡片）同时恢复 backdrop-filter。
   c. 如果列表页的卡片重新排序、摘要重新测量、.no-blur 移除
      三件事同时发生，主线程会阻塞。
3. 关键：.no-blur 移除应该延迟到所有 DOM 更新完成之后。

【排查 5：编辑页滑出时的编辑器状态】
1. 检查编辑页的 contenteditable 是否在滑出时还在计算布局：
   a. 滑出期间，编辑器是否还被浏览器当作"活动编辑区"？
   b. 是否有任何 input / composition 事件在滑出期间触发？
2. 检查编辑页的元素数量：
   a. 图片多的时候，滑出更卡？
   b. 文字多的时候，滑出更卡？
3. 关键：如果编辑器的 DOM 结构复杂，滑出时浏览器可能还在
   重新计算文本布局。

【排查 6：动画本身的性能】
1. 编辑页滑出的 transform 是 translate3d 还是 translateX？
2. #editor-view 和其子元素是否有 will-change？
3. 滑出期间是否有多层 backdrop-filter 同时重绘？

═══════════════════════════════════════
修复方向（供参考，以排查结果为准）
═══════════════════════════════════════

【修复 A：延迟 autosave】
- 如果 blur 触发 autosave 且同步写 IndexedDB：
- 把 autosave 改为异步，或者延迟到返回动画结束后执行。
- 具体：blur 时只标记"有未保存内容"，等返回动画结束（370ms 后）再写入。

【修复 B：延迟 DOM 更新到动画结束后】
- backToList 里的所有 DOM 更新（定向更新、摘要重测、排序移动）：
- 都推迟到返回动画结束后 50ms 执行。
- 动画期间只做：编辑页滑出 + 列表页显示。
- 动画结束后再做：更新卡片内容、重测摘要、重排序、移除 .no-blur。

【修复 C：强制回流合并】
- 如果多个 DOM 操作都需要强制回流，合并成一次。
- 用 requestAnimationFrame 包裹，批量处理。

【修复 D：编辑页的 will-change】
- 编辑页滑出时，给 #editor-view 加 will-change: transform, opacity。
- 滑出结束后 370ms 移除。
- 不要在子元素上重复挂 will-change。
