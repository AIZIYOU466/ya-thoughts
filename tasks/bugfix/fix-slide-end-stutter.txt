═══════════════════════════════════════
现象
═══════════════════════════════════════

编辑页从右侧滑入到屏幕左侧，快要到达终点的最后几毫秒，有轻微卡顿感。

具体描述：
- 动画前面 90% 都很流畅。
- 最后的 10%（接近 translateX(0) 的位置）会有一下顿。
- 用户观感：像动画"刹车"时被绊了一下。

═══════════════════════════════════════
根因排查（systematic-debugging 流程）
═══════════════════════════════════════

按以下顺序排查：

1. **找到编辑页滑入的完整代码路径：**
   a. show('editor') 或等价的进入编辑页函数。
   b. 它用 setTimeout 或 transitionend 做的所有清理操作，分别在什么时刻执行？
   c. 清理操作的清单（列出所有）：
     · 移除 .entering 类
     · 移除 .no-blur 类
     · 隐藏 listView（visibility: hidden）
     · 移除 will-change
     · 移除 .active / .leaving
     · 其他 DOM 操作

2. **检查这些清理操作的执行时机：**
   a. 是在动画进行中执行，还是在动画完全结束后？
   b. 如果是 setTimeout(320)，可能和 320ms 动画同时触发——在动画的最后一帧执行清理，必然掉帧。
   c. 清理操作是否正确延迟到动画结束后？

3. **检查动画曲线本身：**
   a. 当前用的是 cubic-bezier(0.32, 0.72, 0, 1)。
   b. 这条曲线在 90% 位置的速度是多少？是否在末尾突然"急刹"？
   c. motion-web 里有没有更适合"平滑停住"的曲线？

4. **检查动画期间是否有重复触发：**
   a. requestAnimationFrame 是否重复调用？
   b. 是否有 MutationObserver 或 ResizeObserver 在动画期间频繁触发？
   c. 编辑页内的 contenteditable 是否在动画期间重新计算布局？

5. **检查动画元素的层级：**
   a. #editor-view 是否有 will-change: transform, opacity？
   b. 它的子元素（.editor-panel、.editor-bar 等）是否也带了 will-change？
   c. 如果子元素也有 will-change，会创建多个合成层，影响性能。

6. **检查硬件加速是否生效：**
   a. transform: translateX 是否用了 translate3d？
   b. 是否用了 transform: translateX(0) 还是 translate3d(0, 0, 0)？
   c. 用 translate3d 触发 GPU 加速更可靠。

═══════════════════════════════════════
修复方向
═══════════════════════════════════════

【修复 1：延迟所有清理操作到动画结束后 50ms】
- 找到 setTimeout(320) 之类的清理逻辑。
- 把它改成 setTimeout(370)（动画 320ms + 50ms 余量）。
- 用 transitionend 事件更准，但要确保只监听一次，且校验 e.propertyName === 'transform' 或 'opacity'。
- 关键：清理操作（移除 will-change、隐藏 listView 等）不要在动画进行中执行。

【修复 2：优化动画曲线，让结尾更平滑】
- 当前 cubic-bezier(0.32, 0.72, 0, 1) 尾部有"急停"感。
- 改用更缓的收尾曲线，比如：
  cubic-bezier(0.22, 1, 0.36, 1)（更容易"减速到停"）
  或者：
  cubic-bezier(0.16, 1, 0.3, 1)（更柔和的减速）
- 时长可以从 320ms 延长到 340ms，给足减速时间。

【修复 3：确保用 translate3d 触发 GPU 加速】
- #editor-view 的 transform 用：
  transform: translate3d(100%, 0, 0)  ← 起始态
  transform: translate3d(0, 0, 0)     ← 终态
- 不要用 translateX(100%)，有时不触发 GPU 加速。

【修复 4：检查并移除多余的 will-change】
- #editor-view 自己有 will-change: transform, opacity 就够了。
- 如果它的子元素也有 will-change，移除（避免多层合成）。
- will-change 只在动画期间挂，动画结束后 370ms 移除。

【修复 5：确保列表页的 visibility 切换正确延迟】
- 如果列表页的 visibility: hidden 在动画最后一帧执行，也会掉帧。
- 确认它在 370ms 之后才切换。
