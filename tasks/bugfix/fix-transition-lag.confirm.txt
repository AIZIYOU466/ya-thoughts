═══════════════════════════════════════
修复 1：补回过渡动画（同意，但要保守）
═══════════════════════════════════════

同意补回 #editor-view 的 transition + .entering / .leaving 规则。

═══════════════════════════════════════
修复 2：.no-blur 的写法要改（重要）
═══════════════════════════════════════

你报告里写的：
.no-blur, .no-blur * {
  backdrop-filter: none !important;
}

这个写法太粗暴。.no-blur * 会命中所有后代元素，
包括弹层内部的玻璃效果、卡片内部的装饰元素。
副作用是切换期间整个页面都变成不透明，视觉会闪。

改成精准写法：
.no-blur,
.no-blur #list-header,
.no-blur #search-wrap,
.no-blur #seg-bar,
.no-blur .new-cap,
.no-blur .editor-panel,
.no-blur .editor-bar,
.no-blur .editor-toolbar {
  -webkit-backdrop-filter: none !important;
  backdrop-filter: none !important;
}

弹层（#menu-pop、#undo-toast、#confirm-modal、#share-card、
#about-card、#img-menu）在页面切换期间通常不显示，可以不加。

═══════════════════════════════════════
修复 3：will-change 只在切换期间挂（同意）
═══════════════════════════════════════

同意在切换期间给 #list-view 和 #editor-view 加 will-change: transform, opacity。
切换结束后 300ms 内移除，避免长期占用 GPU 内存。

═══════════════════════════════════════
执行顺序（重要）
═══════════════════════════════════════

分两步执行，每步做完让用户测试：

【第 1 步：只做修复 1（补回动画）】
- 只补回 #editor-view 的 transition + .entering / .leaving

【第 2 步：根据第 1 步的结果决定】

- 如果动画出现但布局又坏了 → 立即回滚 transform 部分，改用纯 opacity。

不要一次全做完。第 1 步做完暂停，等用户测试结果。
