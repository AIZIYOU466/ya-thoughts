═══════════════════════════════════════
补充约束 1：backdrop-filter 性能边界（重要）
═══════════════════════════════════════

backdrop-filter 在 Android WebView 上是性能重灾区。默认全开会导致列表滚动严重掉帧。

明确规则：
- **卡片（.note-item / .swipe-body）不使用 backdrop-filter。**
  · 改用：半透明白底 rgba(255,255,255,0.72) + 1px 边框 + 阴影 + 内高光
  · 视觉上仍然是"玻璃"，但没有实时模糊的计算开销
- **只有以下"浮层"使用 backdrop-filter:**
  · 顶栏 #list-header
  · 底部胶囊 #new-bar
  · 多选顶栏 #sel-bar
  · ⋯ 菜单
  · confirm 确认框
  · toast
  · 编辑页玻璃面板（决策 2 里新增的）
- 这些浮层数量有限，且在屏幕边缘，不会随列表滚动重绘，性能可接受。

删掉报告里"IntersectionObserver 动态开关"的方案——那是多余的复杂度。

═══════════════════════════════════════
补充约束 2：任务 3 深色模式下的液态玻璃
═══════════════════════════════════════

深色模式下的玻璃质感不能只是"白底变黑底"。
- 亮色：玻璃 = 半透明白 + 冷色渐变底 + 浅蓝阴影
- 深色：玻璃 = 半透明深灰 + 更深蓝渐变底 + 淡蓝内高光
  · --glass-bg: rgba(38, 42, 52, 0.6)
  · --glass-border: rgba(120, 160, 220, 0.15)
  · --glass-highlight: inset 0 1px 0 rgba(180, 200, 240, 0.12)
  · 页面渐变深色：从 #14171F 到 #1A2030（带一点蓝紫调）

═══════════════════════════════════════
补充约束 3：任务 2 返回闪动的补充修复方向
═══════════════════════════════════════

你在报告里提到"下一个嫌疑是编辑页 transform 滑出与 #list-header 的 backdrop-filter 在 Android WebView 的合成闪白"——这个判断可能是对的。

加一层保险修复：
- 编辑页滑出时，给 #list-header 临时加一个类 .freeze-blur，让它在这一帧内 backdrop-filter: none，滑出结束后恢复。
- 编辑页滑出用 transform: translateX(100%) + opacity，不要用 display 切换。
- 滑出时长 260ms，cubic-bezier(0.32, 0.72, 0, 1)。
- 滑出结束后，编辑页用 visibility: hidden + pointer-events: none 隐藏，不要 display: none（避免下次打开时重播动画）。

═══════════════════════════════════════
补充约束 4：任务 5 时间显示的容错
═══════════════════════════════════════

- 如果 updatedAt < createdAt（用户改了手机时钟），以 createdAt 为准，不显示负数。
- 如果 createdAt 缺失（老数据），用 updatedAt 兜底。
- relativeTime 的边界：
  · < 60s：刚刚
  · < 3600s：X 分钟前
  · < 86400s：X 小时前
  · < 7 天：X 天前
  · < 30 天：X 周前
  · < 365 天：X 个月前
  · ≥ 365 天：X 年前
- 单数复数无需处理（中文无复数）。
