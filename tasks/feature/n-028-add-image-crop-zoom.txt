═══════════════════════════════════════
阶段 1：图片裁剪
═══════════════════════════════════════

【用户流程】
1. 用户在编辑页点"图片"胶囊 → 从相册选图。
2. **选中后不直接插入，而是弹出裁剪界面**。
3. 用户在裁剪界面调整图片位置和大小。
4. 点"确认"→ 用 Canvas 输出裁剪后的图 → 插入到编辑器。
5. 点"取消"→ 放弃这次选图，回到编辑页。

【裁剪界面设计】
- 全屏 overlay，背景深色半透明（rgba(0,0,0,0.92)）。
- 中间：一个固定比例的裁剪框（默认 1:1 正方形）。
- 裁剪框内显示待裁剪的图片，图片可以：
  · 单指拖动（平移）
  · 双指捏合（缩放）
  · 图片不能拖出裁剪框范围之外（保持裁剪框始终有图）。
- 裁剪框外区域显示为半透明黑色遮罩，突出裁剪框。
- 裁剪框四角有小的白色直角标记（视觉提示）。

【底部工具栏】
- 左："取消"文字按钮（灰色）
- 中：比例切换（1:1 / 4:3 / 16:9 / 原图，4 个小图标）
- 右："确认"文字按钮（主色 #2E6BE6）

【技术实现】
1. 用户选图后，用 FileReader 把图片读成 DataURL 或 Blob。
2. 创建一个 <img> 元素加载图片，获取原始宽高。
3. 在 overlay 里显示图片 + 裁剪框。
4. 用 touchstart / touchmove / touchend 处理拖动和缩放（不用 Pointer Events）。
5. 缩放范围：0.5x ~ 5x（基于图片的初始适配尺寸）。
6. 点"确认"时：
   a. 计算裁剪框在图片上的实际像素区域。
      · 需要把裁剪框的屏幕坐标转换成图片原始坐标。
      · 考虑图片的缩放比例和偏移。
   b. 创建一个 Canvas，尺寸 = 裁剪区域的原始像素尺寸。
   c. canvas.getContext('2d').drawImage(img, sx, sy, sw, sh, 0, 0, sw, sh)。
   d. canvas.toBlob(callback, 'image/jpeg', 0.85) 输出压缩后的 Blob。
   e. 把 Blob 存进 IndexedDB 的 images store（复用现有的 insertImage 逻辑），
      插入到编辑器光标处。
7. 点"取消"→ 关闭 overlay，不插入任何东西。

【边界情况】
- 图片加载失败：toast 提示"图片加载失败"，关闭 overlay。
- 图片太小（< 100px）：跳过裁剪，直接插入原图。
- 用户在裁剪界面按系统返回键：等同"取消"。

【浏览器兼容】
- Canvas 的 toBlob 在 Android WebView 支持良好，可以用。
- 如果 toBlob 不可用（旧浏览器），回退到 toDataURL('image/jpeg', 0.85)，
  再转成 Blob。

═══════════════════════════════════════
阶段 2：查看器双击缩放
═══════════════════════════════════════

【用户流程】
1. 用户在编辑页点击图片 → 打开全屏查看器。
2. 双击图片 → 以双击点为中心放大到 2.5x。
3. 再次双击 → 缩回到 1x，位置复位。
4. 查看器已有的双指捏合缩放和单指拖拽平移保持可用。

【双击检测（关键）】
- 记录上一次点击的时间和位置：
  · lastTapTime
  · lastTapX
  · lastTapY
- 当收到一次点击（touchend 或 click）时：
  · 如果 (currentTime - lastTapTime) < 300ms
    且 (|currentX - lastTapX| < 30px) 且 (|currentY - lastTapY| < 30px)
    → 判定为双击
  · 否则记录这次为"上一次点击"，等待下一次
- 双击后清空 lastTapTime，避免连续三次点击触发两次缩放。

【双击缩放的实现】
- 查看器的图片元素已有 transform 状态（由捏合缩放控制）。
- 用 CSS transform: translate(x, y) scale(s) 组合。
- 双击放大：
  · 目标 scale = 2.5
  · 目标平移 = 让双击点保持在屏幕原位
    · 计算：newTranslateX = tapX - (tapX - currentTranslateX) / currentScale * 2.5
    · newTranslateY 同理
  · 用 CSS transition: transform 300ms cubic-bezier(0.4, 0, 0.2, 1)
- 双击缩小：
  · 目标 scale = 1
  · 目标平移 = (0, 0)
  · 同样 300ms transition

【和捏合缩放的冲突处理】
- 捏合手势触发时，取消双击计时器（如果正在等第二次点击）。
- 捏合期间（两指同时按下），不响应双击。
- 双击后 300ms 内，忽略单指拖拽（防止双击的第二次 touchend 触发拖拽）。
- 关键：用一个 gestureMode 变量区分状态：
  · 'idle'：无手势
  · 'pinching'：正在捏合
  · 'dragging'：正在拖拽
  · 'doubletap-pending'：等待第二次点击
  · 只有 'idle' 或 'doubletap-pending' 时才检测双击

【双击的视觉反馈】
- 双击瞬间，图片轻微缩放（scale 1.02）作为触觉提示，然后开始放大动画。
- 或者不用反馈，直接执行 300ms 的放大动画，干净利落。
- 推荐后者（更简洁）。
